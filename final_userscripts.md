# Пользовательские сценарии проекта Steam Analysis

## Сценарий 1. Поиск игры по названию (базовый)

1. Пользователь открывает сайт Steam Analysis.
2. Видит строку поиска в центре экрана.
3. Кликает в поле ввода.
4. Набирает первые 3 буквы названия игры (например, "bal").
5. Система подсказывает варианты: "Baldur's Gate 3", "BallisticNG".
6. Пользователь выбирает "Baldur's Gate 3" из выпадающего списка.
7. Нажимает нажимает "Baldur's Gate 3" в результатах поиска.
8. Открывается страница с таблицей аспектов для этой игры.
9. Пользователь видит, какой аспект хвалят больше всего (например, "сюжет" 92%).

---

## Сценарий 2. Фильтрация игр по минимальному проценту положительных упоминаний

1. Пользователь на главной странице выбирает фильтры.
2. Видит фильтр "Aspect" с выпадающим списком.
3. Выбирает "Gameplay".
4. Видит ползунок "Minimum positive".
5. Перетаскивает ползунок на значение 80%.
6. Нажимает кнопку "Apply filter".
7. Система выводит список игр, где геймплей хвалят в ≥80% упоминаний.
8. Пользователь видит 12 игр, включая "Hades" и "Baldur's Gate 3".
9. Кликает по "Hades", чтобы посмотреть детали.

---

## Сценарий 3. Исключение нейтральных
1. Пользователь ищет игру/находит по фильтрам.
2. Пользователь открывает страницу  игры.
3. Хочет посмотреть таблицу без учета нейтральных отзывов
4. Нажимает "Exclude neutral mentions".
5. Таблица перестраивается: для таблицы показывается только % положительных и % отрицательных (нейтральные обнулены).
6. % положительных и % отрицательных пересчитывается.
7. Пользователь видит, что у игры 15% положительных и 85% отрицательных по оптимизации.
8. Сравнивает с аспектом "графика" (90% положительных).
9. Делает вывод: графика хорошая, но игра тормозит.

---

## Сценарий 4. Сортировка таблицы аспектов по количеству упоминаний

1. Пользователь находится на аналитической странице игры.
2. Видит список Sort by:
3. Выбирает Mentions.
4. Таблица сортируется по возрастанию количества упоминаний аспекта.
5. Пользователь видит какие аспекты упоминаются реже всего.
6. Пользователь нажимает галочку "Descending".
7. Таблица сортируется по убыванию.
8. Пользователь видит, какие аспекты упоминаются чаще всего.
9. Понимает, какие аспекты наиболее важны для игроков.

---

## Сценарий 5. Фильтрация по нескольким аспектам одновременно (AND)

1. Пользователь заходит в "Расширенный поиск".
2. Выбирает из списка два аспекта: "сюжет" и "геймплей".
3. Устанавливает порог для сюжета: ≥70% положительных.
4. Устанавливает порог для геймплея: ≥60% положительных.
5. Нажимает "Найти игры, где хорошо и то, и другое".
6. Система показывает 8 игр.
7. Пользователь видит "Disco Elysium" (сюжет 94%, геймплей 78%).
8. Кликает по игре, чтобы проверить детали.
9. Использует результат как референс для своего проекта.

---

## Сценарий 6. Фильтр по дате добавления отзывов (только свежие)

1. Пользователь открывает страницу игры, вышедшей 2 года назад.
2. Нажимает кнопку "Период анализа".
3. Выбирает "Последние 3 месяца".
4. Нажимает "Обновить".
5. Система пересчитывает метрики только по отзывам за последние 90 дней.
6. Таблица аспектов меняется.
7. Пользователь видит, что раньше хвалили "сюжет", а в последних отзывах ругают баги.
8. Сравнивает с режимом "За всё время" (кнопка "Сбросить период").
9. Понимает, как менялось мнение игроков после обновлений.

---

## Сценарий 7. Поиск игры с низким процентом отрицательных упоминаний по конкретному аспекту

1. Пользователь хочет найти игру, которую не ругают за "оптимизацию".
2. На главной странице нажимает "Расширенный поиск".
3. Выбирает аспект "оптимизация".
4. Выбирает тип фильтра "Доля отрицательных".
5. Устанавливает максимум 10%.
6. Нажимает "Поиск".
7. Система показывает игры, где оптимизацию ругают менее чем в 10% упоминаний.
8. Пользователь видит список из нескольких игр или начинает писать название.
9. Выбирает одну для анализа механик.

---
## Сценарий 8. Поиск похожих игр

1. Пользователь открывает страницу игры.
2. Нажимает кнопку "Похожие игры".
3. Система анализирует игру.
4. Система показывает список похожих игр.
5. Пользователь выбирает игру из списка.
6. Открывается страница выбранной игры.
7. Пользователь просматривает её аспекты.
8. Сравнивает результаты с исходной игрой.
9. Выбирает интересующую игру для дальнейшего анализа.

---

## Сценарий 9. Сравнение двух игр

1. Пользователь открывает игру А.
2. Нажимает "Добавить к сравнению".
3. Открывает игру Б.
4. Нажимает "Добавить к сравнению".
5. Переходит в раздел "Сравнение".
6. Система показывает данные обеих игр рядом.
7. Пользователь выбирает интересующий аспект.
8. Система показывает показатели обеих игр по этому аспекту.
9. Пользователь сравнивает результаты.
