# Пользовательские сценарии проекта Steam Analysis

## Сценарий 1. Поиск игры по названию (базовый)

1. Пользователь открывает сайт Steam Analysis.
2. Видит строку поиска в центре экрана.
3. Кликает в поле ввода.
4. Набирает первые 3 буквы названия игры (например, "bal").
5. Система подсказывает варианты: "Baldur's Gate 3", "BallisticNG".
6. Пользователь выбирает "Baldur's Gate 3" из выпадающего списка.
7. Нажимает нажимает "Baldur's Gate 3" в результатах поиска.
8. Открывается страница с таблицей аспектов для этой игры.
9. Пользователь видит, какой аспект хвалят больше всего (например, "сюжет" 92%).

---

## Сценарий 2. Фильтрация игр по минимальному проценту положительных упоминаний

1. Пользователь на главной странице выбирает фильтры.
2. Видит фильтр "Aspect" с выпадающим списком.
3. Выбирает "Gameplay".
4. Видит поле Minimum positive".
5. Пишет значение 80.
6. Нажимает кнопку "Search".
7. Система выводит список игр, где геймплей хвалят в ≥80% упоминаний.
8. Пользователь видит 12 игр, включая "Hades" и "Baldur's Gate 3".
9. Кликает по "Hades", чтобы посмотреть детали.

---

## Сценарий 3. Исключение нейтральных
1. Пользователь ищет игру/находит по фильтрам.
2. Пользователь открывает страницу  игры.
3. Хочет посмотреть таблицу без учета нейтральных отзывов
4. Нажимает "Exclude neutral mentions".
5. Таблица перестраивается: для таблицы показывается только % положительных и % отрицательных (нейтральные обнулены).
6. % положительных и % отрицательных пересчитывается.
7. Пользователь видит, что у игры 15% положительных и 85% отрицательных по оптимизации.
8. Сравнивает с аспектом "графика" (90% положительных).
9. Делает вывод: графика хорошая, но игра тормозит.

---

## Сценарий 4. Сортировка таблицы аспектов по количеству упоминаний

1. Пользователь находится на аналитической странице игры.
2. Видит список Sort by:
3. Выбирает Mentions.
4. Таблица сортируется по возрастанию количества упоминаний аспекта.
5. Пользователь видит какие аспекты упоминаются реже всего.
6. Пользователь нажимает галочку "Descending".
7. Таблица сортируется по убыванию.
8. Пользователь видит, какие аспекты упоминаются чаще всего.
9. Понимает, какие аспекты наиболее важны для игроков.

---

## Сценарий 5. Фильтрация по нескольким аспектам одновременно
1. На главной странице в панели фильтров пользователь открывает список "Select aspect..." первой строки.
2. Выбирает первый аспект "Story, Characters & Lore".
3. В числовом поле "Min Positive %" первой строки вводит значение 70.
4. Нажимает кнопку "+ Add Aspect" для добавления второй строки параметров.
5. Во второй строке открывает список "Select aspect..." и выбирает "Gameplay".
6. В числовом поле "Min Positive %" второй строки указывает значение 60.
7. Нажимает кнопку "Search" в правой части панели фильтров.
8. Система находит игры, удовлетворяющие обоим критериям одновременно.
9. Пользователь видит карточку игры (например, "Disco Elysium") и кликает по ней для детального анализа.

---

## Сценарий 6. Фильтр по дате добавления отзывов
1. Пользователь открывает детальную страницу игры, вышедшей несколько лет назад.
2. Изучает сводную таблицу аспектов, рассчитанную по отзывам за все время существования игры.
3. В блоке информации рядом с обложкой находит кнопку-переключатель "Filter: Last 90 days".
4. Нажимает кнопку "Filter: Last 90 days".
5. Кнопка окрашивается в зеленый цвет и меняет свой текст на "Showing last 90 days".
6. Система отправляет запрос к API с параметром days=90 и пересчитывает таблицу только по свежим отзывам.
7. Таблица аспектов обновляется, отображая динамику оценок игроков за последние 3 месяца.
8. Пользователь видит изменения в отзывах (например, исправление багов и рост позитива по оптимизации).
9. Повторно нажимает кнопку "Showing last 90 days", возвращая таблицу к отображению статистики за все время.

---

## Сценарий 7. Поиск игры с низким процентом отрицательных упоминаний по конкретному аспекту
1. На главной странице пользователь обращается к панели фильтров каталога.
2. В выпадающем списке "Select aspect..." выбирает технический аспект "Performance".
3. Поле ввода "Min Positive %" оставляет пустым.
4. Переходит к соседнему числовому полю с плейсхолдером "Max Negative %".
5. Вводит максимальный допустимый порог негатива — значение 10.
6. Нажимает кнопку "Search" для запуска фильтрации.
7. Система отбирает в базе данных игры, у которых доля жалоб на производительность не превышает 10%.
8. Каталог обновляется с индикатором "Games found: N", выводя карточки стабильных проектов.
9. Пользователь кликает по карточке подходящей игры для перехода к детальной статистике.

---

## Сценарий 8. Поиск похожих игр
1. Пользователь открывает детальную страницу интересующей игры (например, "Hades").
2. Прокручивает страницу вниз под основную таблицу аспектов.
3. Находит секцию рекомендаций с заголовком "You might also like".
4. Алгоритм бэкенда автоматически отбирает игры со схожим профилем сильных сторон.
5. В карточках рекомендаций пользователь видит обложки, названия и бейджи (например, "4 shared strengths").
6. Выбирает наиболее интересный проект из предложенного списка рекомендаций.
7. Кликает по карточке похожей игры в блоке "You might also like".
8. Приложение бесшовно открывает страницу выбранной игры с ее собственной аспектной таблицей.
9. Пользователь сопоставляет сильные стороны новой игры с исходным проектом.

---

## Сценарий 9. Сравнение двух игр
1. Пользователь находит первую игру в каталоге или открывает ее карточку и отмечает чекбокс "Add to compare".
2. В верхнем меню счетчик на кнопке сравнения обновляется: "Compare (1)".
3. Пользователь находит вторую игру и также отмечает чекбокс "Add to compare" (счетчик становится "Compare (2)").
4. В верхней навигационной панели нажимает активную синюю кнопку "Compare (2)".
5. Открывается экран "Game Comparison" со сводной таблицей сравнения обеих игр по аспектам.
6. Ячейка игры, лидирующей по конкретному аспекту, автоматически подсвечивается зеленым фоном (is-winner).
7. При необходимости пользователь отмечает чекбокс "Exclude Neutral Reviews" для отсечения нейтральных оценок.
8. Пользователь детально сопоставляет показатели обеих игр по ключевым для него аспектам.
9. По завершении анализа нажимает кнопку "Back to list" для возврата или "Clear All" для сброса сравнения.
